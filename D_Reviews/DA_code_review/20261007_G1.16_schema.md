## Two absences that are deliberate, recorded so a later reviewer does not "fix" them

1. **No unique constraint on `(business_date, content_hash)`.** REG-16 requires two generations from
   the same data to produce the *same* hash, and both to be stored as separate reports. A uniqueness
   constraint would make the criterion unsatisfiable.
2. **No foreign key on `generated_by`.** A demo reset deletes and reloads `app_user`; a foreign key
   would either fail the reset or cascade report history away. Same reasoning, and same shape, as
   `import_batch.uploaded_by`.

## One consequence worth knowing before G1.17 and G1.18 build on it

The figures are not columns — they are in the stored copy at `storage_path`, with `content_hash` over
it. That is what REQ-REG-10A asks for and it keeps a reopened report identical to what it said. The
consequence is that reports cannot be *queried* by their contents: "which reports showed more than ten
overdue validations" needs reading every stored copy. Nothing in REQ-REG-10A, REG-15, REG-16 or REG-17
asks for that, so this is not a finding — but if such a question is ever wanted, it is a new column or
a summary table, not a change to this one. Cheap to add later, so the shape is right now.
