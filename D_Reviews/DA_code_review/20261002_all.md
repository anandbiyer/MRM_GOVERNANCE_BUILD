### Overall picture

This is a disciplined, well-layered build and the invariants that matter most hold. I checked every
one in Procedure step 4 and report honestly where they hold: **`app/rules/` is completely pure** — no
`Session`, no `sqlalchemy`, no `open(`, no `requests`, no `date.today` anywhere in the eight rules
modules. **`date.today()` appears exactly once in the whole backend, inside `app/clock.py`.** **Every
material write in `app/services/` is paired with `app.audit.service.record(...)` in the same
transaction** — I walked all twelve service modules and every `db.commit()` has its audit call before
it, with no intervening commit; the bulk reset is the one aggregate event and it is deliberate and
documented. **No route in `app/api/` writes directly to a table**, and **every mutating route is
authorised server-side** (either by `deps.require(Permission.X)` or by an `access.ensure_*` /
`has_permission` check that is the first thing the service does). **Optimistic concurrency is real**:
`row_version` is a required field in every update schema, so INV-06 cannot be bypassed from the client.
**Derived state is genuinely computed on read** — `governance_view.derive` recomputes revalidation,
ageing, MRC status and the explainable score on every request. **The template registry is the single
source of truth** and preview and load share one code path. **The snapshot convention holds**: all ten
files modified under `A_Codes/` since the last commit have a matching `_OLD/` copy.

The two High findings are both the same invariant — "no business number in code" — leaking in two
places that were missed: the governance score bands 60 and 80 are hard-coded in three files with no
`policy_setting` behind them, and the lifecycle phase name `"Monitoring"` is hard-coded in three
places, one of which raises an unhandled `ValueError` (HTTP 500 on the Command Center) if an Admin
edits the `lifecycle_phases` policy list. The Medium findings are mostly configurability drift of the
same family — decision and status vocabularies that are policy lists but are branched on by literal —
plus one UI cache gap that makes the Command Center lag a change by up to 30 seconds, and one
tile-vs-drill-down count mismatch against CC-01.

Nothing I found lets data be written without an audit event, lets a client bypass authorization, or
gets a core calculation wrong.

## 4. Findings

### CR-01 | **High** | Part 0 "no business number in code", §69, SCR-04 | Governance score bands 60 and 80 are hard-coded in three files

The score bands that drive the Command Center distribution, the Operations Board drill-downs and
every score pill are literals. There is no `policy_setting` row behind them.

Evidence:
- `A_Codes/AB_backend/app/services/governance_view.py:148-150` — `s.score.overall < 60`, `60 <= … < 80`, `>= 80`
- `A_Codes/AB_backend/app/services/dashboard_service.py:70` — `"below_60" if v < 60 else "60_80" if v < 80 else "80_plus"`
- `A_Codes/AB_backend/app/services/dashboard_service.py:80-81` — band keys repeated
- `A_Codes/AC_frontend/src/components/Pills.tsx:24` — `n >= 80 ? good : n >= 60 ? warn : bad`
- `A_Codes/AC_frontend/src/pages/CommandCenter.tsx:25,27-28` — tone, label and flag maps
- `A_Codes/AC_frontend/src/pages/OperationsBoard.tsx:22-24` — filter labels
- `B_Inputs/AA_bootstrap/T12_policy_settings.csv` — no score-band key exists

Suggested fix: add `score_band_warn_min` (60) and `score_band_good_min` (80) as T12 integer settings,
read them in `governance_view.FLAGS` and `dashboard_service.summary`, and return them in
`/api/models/meta` so the frontend labels and pill tones derive from the same values.

### CR-02 | **High** | Part 0 "no business number in code", §8, §69 | The lifecycle phase name `"Monitoring"` is hard-coded, and one use raises an unhandled 500

`lifecycle_phases` is a configurable T12 list (`B_Inputs/AA_bootstrap/T12_policy_settings.csv:29`) and
is editable through `PUT /api/admin/policy` with no key-specific validation
(`A_Codes/AB_backend/app/rules/policy_values.py:45-58` has no rule for it). Three places assume the
literal `"Monitoring"`:

- `A_Codes/AB_backend/app/services/dashboard_service.py:64-65` — `policy.phases.index("Monitoring")`
  with **no guard**. Rename or remove the phase and `GET /api/dashboard/summary` raises `ValueError`
