## 7. Verdict input

Gate 0 did what it set out to do. All eighteen landed rows are real: every mechanism each row claims
is in the code, and every test each row names exists. The two High findings from 2026-10-02 are
properly closed, not papered over — the score bands and the monitoring phase are genuinely single-sourced
from `policy_setting` now, with the derived-column order consolidated into one function that degrades
instead of raising, and the band keys deliberately carry no numbers. Four of the eight Mediums are
closed as well, and the audit, authorization, clock, layering and registry invariants all hold under a
call-by-call re-check.

Two things stand in the way of a clean exit. The first is that the "no business number in code"
invariant is still broken in the *same* way, one file across: `document_rules.required_types` picks a
required-document list by comparing against three literal phase names, and the paired policy validation
G0.1 added protects only `monitoring_phase` out of the six settings that name a phase. The failure mode
is the one CR-02 described — silent, score-affecting, no error — and G0.1's own note spotted it and
deferred it to a finding that was never given a row. The second is that four Gate 0 edits were committed
without the `_OLD/` snapshot the repository's first convention requires, one of them to the governance
score rules module, which has no snapshot at any version. Both are mechanical to fix.

Alongside them, the gate's own closure record is incomplete: thirteen of the twenty findings this gate
was convened to close have no row, no Backlog entry and no recorded dismissal, so "Gate 0 closed out the
first review" cannot currently be evidenced for most of it.

My recommendation on the requirements half: **not Ready until CR-21 and CR-22 are fixed and CR-23 is
discharged by a triage pass.** None of the three needs new design, and none touches data integrity,
security or the demo path — so they are small rows, not a reopened gate.
