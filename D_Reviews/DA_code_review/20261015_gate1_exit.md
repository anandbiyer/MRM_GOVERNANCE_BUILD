## 6. Spec issues

- **SI-1. GEN-04 and GEN-05 still describe the mechanism G1.32 replaced.** No §81A decision exists.
  GEN-05 (`claude.md:3455-3457`) says a failed job "marks its own batch Failed … so the signal
  cannot report a reset in progress for ever; a batch left non-terminal … can be cancelled through
  the API." The signal is now the lock (`app/api/admin.py:38-53`). Cancelling a batch does not
  release it. The escape for a held lock is a restart (`app/main.py:17-34`), and there is no API to
  release it (TR-75, BL.38). GEN-04 says the refusal "names the batch in flight". During "Starting"
  or "Seed preparation" no batch exists yet, and the message says "(being created)"
  (`reset_service.py:257`). After a database-lock refusal it names nothing (`:253-254`). I am not
  judging which side should change. The criterion text should describe the lock (held from claim to
  final release, released on any failure, recovered at startup), or the owner should decide that an
  API release is required.
- **TR-83** (held). The seeded example's reconciliation line states its shaped `generated_at`. This is
  still open and still needs the owner's decision. The code is unchanged.
- **PLT-03 "the number checked is reported."** Commits or files? The control reports commits
  (`check_snapshots.py:178`). TR-53 asked for files, because only a file count exposes a silently
  dropped file (CR-68). The wording should say which.
