## 4. Findings

| ID | Severity | MUP-ID | Difference | Suggested fix |
|---|---|---|---|---|
| **MP-01** | **Critical** | MUP-01…06, 34 | **After the documented "Reset to seed", the Command Center returns HTTP 500 and never renders.** `B_Inputs/AC_seed/T12_policy_settings.xlsx` carries 60 policy keys; `B_Inputs/AA_bootstrap/T12_policy_settings.csv` carries 62. `production_phases` and `insights_display_limit` exist only in the bootstrap file, and `reset_service` deletes `policy_setting` and reloads it from the seed alone, so both vanish. `GET /api/dashboard/summary` then raises `PolicyMissingError`: *"Policy setting 'production_phases' is not configured."* Verified directly (500), and the dashboard returned 200 immediately after `app.cli bootstrap` restored the two keys — nothing else changed. | Regenerate `AC_seed/T12` from the current policy set, and make the seed/bootstrap key sets diverge loudly: have `reset_service` fail if a key the rules require is absent, rather than leaving a 500 for the first user to find. Add a test that resets from the **committed** seed (see MP-02). |
| **MP-02** | **High** | — (process) | **No test can catch MP-01.** `test_tc_gen_01_reset_to_seed` runs with `regenerate_seed_on_reset=True` against a seed generated into `tmp_path`, so the committed `B_Inputs/AC_seed` files are never loaded by any automated test. The only coverage of the artefacts that ship to a new machine is a human running the launcher. | Add one test that resets with `regenerate_seed_on_reset=False` against the committed seed and then calls `/api/dashboard/summary`, asserting 200. It would have failed today. |
| MP-03 | Low | MUP-34 | The cross-screen count check is flaky: passes in isolation (256 Command Center total == 256 Operations Board rows) but intermittently reads 0 rows in a full run — a render race in the harness, not a disagreement between screens. | Poll the row count to a stable value before comparing, or compare against the board's own reported count rather than DOM rows. |
| MP-04 | Low | — (harness) | Part 0 and the agent spec say to wait on `http://127.0.0.1:5173`, but `AC_frontend/vite.config.ts` sets no `host`, so Vite binds to `localhost` (::1) only and `127.0.0.1` refuses the connection. The harness uses `localhost`. | Correct the address in Part 0 and the agent spec, or set `server.host` in `vite.config.ts`. |
| MP-05 | Low | MUP-02 | The mock-up draws donuts with percentage labels; the app draws horizontal bar lists with counts and percentages. Same categories, same drill-downs. | None required — the BRD (§52) mandates the visual language, not the chart type. Recorded so the difference is deliberate rather than overlooked. |
| MP-06 | Low | MUP-23 | The checklist item names a specific outcome (4 loaded, 1 rejected, message naming field and row). The parity test only asserts the upload controls exist, because loading the demo file mutates the database mid-review. The outcome itself is proven by backend test `test_tc_imp_03_1_preview_then_partial_load`. | Either accept the backend test as the evidence for this item, or give the harness a disposable database so it can drive the full import. |

No **Missing** and no **Accepted difference** findings: every built screen matched.

### Harness defects corrected during this review

All of these were faults in the newly written `A_Codes/AF_e2e` harness, not in the product. Recorded
because the parity statuses above depend on them, and because the pattern — content behind tab groups —
will catch the next person writing a test too.

| Harness fault | Affected | Cause |
|---|---|---|
| Panels behind tabs never opened | MUP-14, 15, 16, 17, 21 | Model 360 defaults to the Overview tab (`Model360Page.tsx` `TABS`) |
| Tab name matched exactly | MUP-14, 16 | Findings/Approvals tabs append a `<span class="count">` badge, so the accessible name reads "Findings4" |
| Import registry not found | MUP-22 | Import Centre has its own tabs (Upload / Templates / History), defaulting to Upload |
| File inputs not found | MUP-25 | Document Centre tabs (Register / Upload / Batches / Completeness), inputs hidden behind buttons |
| `exact: true` on a panel heading | MUP-02, 03 | `BarList` renders `<h4>{title}{note && <small>…</small>}</h4>`, so "Lifecycle stage" never matches exactly |
| Bar rows treated as links | MUP-03 | They are `<button class="barrow">` |
| `getByLabel("Stage")` ambiguous | MUP-21 | Matches both the filter select and the sortable column header |
| Tile value mis-parsed | MUP-34 | Scraped the whole tile (label + value + sub-line); the number is in its `<b>` |
| Exactly-one file input asserted | MUP-23 | There are two (files and folder) |
