## 3. Answers to the questions asked

1. **Does the new test discriminate CR-52?** Yes. M1 fails the REG-16 test on the hash itself.
   **Does it discriminate the class?** No. The S13 structural test compares "no predecessor" with "a predecessor that has seen everything". In both cases every "since" list is empty, so its loop is blind to any figure of the form "things not in the previous baseline". M1 is caught only by the hard-coded key-set pin, and M3 (the same defect in another section) passes everything.
2. **Is anything else still predecessor-derived outside `changes_since`?** No. I read `sections()` and every builder. `inventory`, `validation`, `findings`, `approvals`, `score`, `documentation` and `baseline` are built only from `dashboard_service.summary`, `governance_view.portfolio` and current rows. `previous_content` reaches only `seen_before`, which feeds only `_decisions_recorded` and `_changes_since`. In `generate()`, `previous_report_id` goes into the row and the audit `after` only, not the hash.
3. **Does the hash still move on a real figure?** It does today: the exclusion is still exactly `k != "changes_since"`. But the only test is a single model-creation probe, which changes inventory, score, documentation and baseline together. Widening the exclusion by a whole section (M2, M6) is therefore not detected (TR-62).
4. **Are the permission and audit halves of REG-16 untouched?** Yes. `generate()` is not in the diff. The tests `test_reg_16_each_generation_writes_exactly_one_audit_event`, `…_a_role_without_report_generate_is_refused_and_nothing_is_stored`, `…_the_service_refuses_an_unpermitted_principal_too`, `…_a_refused_generation_writes_no_audit_event` and `…_report_generate_is_held_by_exactly_the_specified_roles` are unchanged and pass.
5. **Is the legacy fallback sound?** It is safe, because nothing crashes: the API returns `sections: dict` untyped, and the PDF and the page both default to `[]`. It is not truthful. A pre-S13 report's decisions are stored at `approvals.decisions_since_previous`, but that key is no longer rendered anywhere. A reopened legacy report therefore states "Approval decisions recorded: 0" when its own stored copy lists decisions (TR-61). This contradicts S12, under which a reopened report states what was true when it was generated. Exposure is limited: only reports generated on dev databases before this change carry the old shape, and seeded reports always had an empty list.
