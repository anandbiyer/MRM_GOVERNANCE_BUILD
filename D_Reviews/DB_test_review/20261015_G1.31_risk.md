**Is `_pdf_text` vacuous?** No.

- On the seeded PDF it extracts 8,156 characters of page text: header, label, inventory tables and so on.
- The string `Seeded example` does not occur in the raw PDF bytes. It can therefore only come from the decoded ASCII85+Flate page stream.
- The Info `/Title` is present in the raw bytes, but the helper never reads it, because it reads only the `Tj` operands of the decoded streams.
- An empty extraction cannot pass the test. Each PDF has a positive `in` assertion (the reconciliation line), and that assertion comes before the only negative one (`"Seeded example" not in generated_pdf`).

Residual fragility, not a vacuity: ReportLab escapes `(`, `)` and non-Latin-1 characters inside `Tj` strings, and the helper does not unescape them (`\(as displayed\)`, `\267`). Any future assertion containing a parenthesis or a non-ASCII character would fail spuriously. The current assertions contain neither (Low, noted under TR-84's suggestion and not raised separately).

**Re-derivation from `SEED_REPORT_AGE_DAYS`:** none.

- `business_date` is still `today() - SEED_REPORT_AGE_DAYS`, which is unchanged.
- `figures_as_of` is `today()`, stored on the row.
- `seeded_label` reads only the stored `is_seeded`, `figures_as_of` and `business_date`.
- The PDF receives `seeded_label` from `ModelRiskReportOut.model_dump()` in `app/api/reports.py`, so the PDF and the API share one wording.
- The test hard-codes `2026-08-31`. That is an independent hand calculation (30 days before 2026-09-30), not a copy of the offset. M8 confirms that a re-derivation is caught.

**REG-16 does not move.** `figures_as_of` is a column on `model_risk_report`. It is never written into `sections`, and `content_hash` hashes `sections` minus `changes_since` only. The audit `after` payloads are also unchanged. All existing REG-16 tests pass, including `test_reg_16_*` hash equality and the 403 refusal with nothing stored and no audit event. Confirmed.

**Is asserting the label through the API alone adequate?**

- **Reopened report:** adequate. The page renders `report.seeded_label` verbatim, gated on the same field.
- **Report list:** the page renders `r.seeded_label` verbatim in a `.note` under the pill. A regression in the page itself would not be caught by any test, because there is no frontend harness (G7.5) and no `Seeded example` or `seeded_label` assertion exists in `A_Codes/AF_e2e/` (grep: no matches). Examples of such a regression: gating the note on a different field, or dropping it. For a disclosure whose whole purpose is that the reader sees it, that leaves a gap outside CI (TR-86, Low).
