**Scope:** REG-15 and REG-16, the criteria G1.16 carries. Date 2026-10-07 · branch
`gate-1-core-report` · scope digest `35e7e8f51bba178979ed14e286051fa8e57c385b`.

G1.16 is on the risk list because it adds a permission (`REPORT_GENERATE`) and an audited write —
REG-16 asserts both, and "nothing is stored and no audit event is written" is the kind of claim a test
can appear to prove while proving nothing.

**Performed by hand, not by the `test-outcome-reviewer` agent** (agent type unavailable to the Agent
tool in this session; see the R1 report). Each criterion was judged by simulating the defect it
describes and checking that the test actually fails, which is the only evidence that counts here.

Files: `tests/test_reports.py`, `app/services/report_service.py`, `app/auth/roles.py`,
`app/api/reports.py`.

## Two findings in the implementation that this checkpoint caused to be fixed

Recorded because they are the substance of what the checkpoint bought, not incidental:

1. **`generated_at` was set from `datetime.now()`** while every other timestamp column uses
   `func.now()`. The clocks differ by the UTC offset, so every "changed since the previous report"
   comparison was wrong — and it showed up as the whole portfolio appearing newly retired. Now the
   column default supplies it, so one clock is used.
2. **"Changes since" compared timestamps at all.** `created_at` and `generated_at` have one-second
   granularity, so anything happening in the same second as a report was invisible — which is
   precisely what a user clicking Generate twice would do. It now diffs an identity `baseline` carried
   in the stored copy, which is also what REG-17 literally asks for ("the differences from the
   previous stored report") and needs no clock. The same change was applied to "decisions since the
   previous report", which had the identical weakness.
