# MRM/MIS — Project Plan

**Status as at:** 2026-10-07 · **Branch:** `gate-1-core-report` (Gate 0 work is on `review-agents`)

*(No commit hash here on purpose: a hash written into a tracked file is stale the moment it is
committed. Evidence columns cite test names and settings, which stay valid.)*

This is the live plan from the current build to a demonstrable product. It is the tracking document:
statuses here are maintained as work lands, and every activity carries a stable ID so it can be
referenced in commits and reviews.

## How to use this file

- **Stable IDs.** `G0.1`, `G1.4` and so on never change meaning or get renumbered. New work gets the
  next free number in its gate; cancelled work is marked `Dropped`, not deleted.
- **Status vocabulary:** `Done` · `In progress` · `Blocked` · `Not started` · `Dropped`.
  `Blocked` always names what it waits on.
- **Evidence.** A `Done` row cites what proves it — a commit, a test, a report path. A row without
  evidence is not `Done`.
- **Update rule.** Update this file in the same change that moves the work, not afterwards. Add a line
  to the change log at the bottom. Keep the "Status as at" line current.
- Findings referenced as `CR-nn` / `TR-nn` / `MP-nn` / `FT-nn` come from `D_Reviews/20261002_summary.md`
  and the reports beneath it — `DA_code_review`, `DB_test_review`, `DC_mockup_review` and
  `DD_functional_test`. `D1`–`D12` are the §81A decisions in `CLAUDE.md`.
- **Findings.** Every review ends with `/triage-review`. Approved findings become rows in the current
  gate (Critical, High and regressions block its exit), attach to a later gate's row, become a §81A
  decision, or are closed as not a defect. A finding's row is `Done` when the issue is `Verified` at a
  gate exit. IDs: `CR-nn` / `TR-nn` / `MP-nn` / `FT-nn`, from the reports under `D_Reviews/`.
- **Reviews.** Review agents run at four points only (CLAUDE.md Part 0, "When reviews run"): a schema
  checkpoint after each gate's migration, a risk checkpoint for activities touching permissions, audit,
  score or tier (currently **G1.16, G1.18, G3.4, G3.10, G3.13, G5.4**; G1.2, G1.6, G1.7, G1.9 and G1.14
  when Phase 2A resumes), a gate exit review, and before merging to `main` or a demo. Other activities
  need no review agent to be `Done`.
  This list is the authority, because two of its entries do not match the criteria-prefix rule and would
  otherwise be missed: **G1.18** writes the REG-16 tests, which assert that a caller without
  `REPORT_GENERATE` is refused and that *nothing is stored and no audit event is written* — a
  permission-and-audit claim under a REG prefix, and exactly the kind of test that can pass while
  proving nothing. **G5.4** requires that nothing persists without human confirmation and that every AI
  step is audited — an audit-in-the-same-transaction claim under a DOC prefix. Add an activity here
  whenever it makes such a claim, whatever its criteria are named.

**The shape of it:** the governance spine is complete — recording and governing a model works end to
end. The measurement half is absent — nothing observes a model over time. That is why 69 of 115
criteria are proven while only about 55% of the data model exists.

### Two demo bars

| Bar | Scope | State |
|---|---|---|
| **A — what exists** | Inventory, tiering, validation, findings, approvals, score, structured import, documents, Command Center, Operations Board, Model 360, Admin, Audit Trail | Near ready; Gate 0 closes it out |
| **B — what the customer saw** | All 35 mock-up items, including monitoring, backtesting, CDE/DQ, the MRC report and the Copilot | Needs Gates 1–6 |

**Recommended target:** Gate 0 → core report (G1.16–G1.18) → Gate 2 decisions → Gate 3. That is the
shortest credible customer demo: the full governance lifecycle, the model risk report and monitoring.
The rest of the SR 26-2 regulatory story is deferred by **D12**. Data Audit, AI extraction and the
Copilot are self-contained and nothing depends on them, so they can be presented as roadmap.

1. **Gate 2 is now the critical path.** With Phase 2A deferred, the core report is the only work that
   runs alongside the D1–D7 decisions. Once it is done, nothing but Gate 5 (AI extraction) can be
   built until D1–D7 are recorded.

   attached means migrating live associations.
4. **Scores move when Gate 3 lands.** Anything quoting today's governance scores — seed expectations,
   demo scripts, GEN-01's documented figures — needs revisiting then.
5. **Reviews run at four fixed points, not continuously.** A merge or push to `main` without a Ready
   gate review of that commit is blocked by a hook; nothing else is.
6. **No deadline estimates appear in this plan deliberately.** There is no velocity data for this team;
   sequencing and dependencies are stated instead, so dates can be attached once capacity is known.
